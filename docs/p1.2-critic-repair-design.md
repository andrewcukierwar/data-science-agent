# P1.2: objective-bound critique and bounded finalization repair

Approved implementation specification, 2026-09-22. Base:
`e4967fbd80cd4c6d77517f704327e151f38596a1`. No live calls are required.

## Contract

Keep P0.1–P1.1 unchanged. Add a versioned validation/repair contract `1.0`
independently of workspace schema 1.2 (whose exact-version binding checks must
remain effective). Old validation records load with a null contract marker;
never upgrade old evidence or change frozen Phase 2 results/evaluation. Strict
output fingerprints change naturally. Future experiments need new immutable
code/configuration identities. No evaluator/task/scenario changes.

Extend `ValidationResult` with typed blockers and limitations, retaining legacy
issues for old records and deterministic gate compatibility. New runtime reviews
are normalized/validated against the candidate and ledger before persistence,
including injected runner outputs. Never interpret unvalidated REVISE as PASS.
Legacy nonempty issues remain blocking conservatively until explicitly adapted;
legacy REVISE without actionable issues terminates constrained, not PASS.

A blocker contains:

- Application-assigned `id`; category enum: wrong_grain, wrong_denominator,
  incorrect_numerical_claim, unsupported_asserted_fact,
  missing_requested_comparison, selected_result_conflict, objective_not_answered.
- `requirement_id`: application catalog ID tied to the immutable original
  objective or an existing deterministic completion rule, never a repair prompt.
- `target_id`: application catalog ID for a selected result, finding, answer,
  or a missing objective/completion requirement. Include affected result IDs
  separately so provenance survives a corrected result's new content identity.
- Inspectable objection evidence, message, smallest feasible repair, and
  repair class enum synthesis_selection, computation, impossible_with_current_data.
- Evidence uses typed anchors: candidate JSON pointer with exact retained value,
  or canonical successful tool-event ID plus JSON pointer and exact retained
  value (arguments or output). Validate pointers and equality, all citations,
  target membership and requirement membership before accepting the review.
  Candidate snapshots establish what was asserted/missing; factual objections
  about data require retained execution evidence. No fabricated event, field,
  value, or checked finding ID may be accepted, even beside valid evidence.

The catalog is deterministic and small: original objective plus existing
completion gate IDs, candidate answer/findings and selected metric/statistical
slots. No model extraction of new task requirements. Metric/statistical slot
anchors use existing normalized scope (metric, dimensions, periods/type), not
value, prose, binding, list position, or incorrect denominator being repaired;
finding anchors use existing finding IDs. Deduplicate ambiguous slots or reject
ambiguous targets. Catalog contents cross the Critic/self-critique boundary.
A new requested-comparison blocker must cite the exact objective clause; the
application checks it occurs in the original objective. Broad material failure
uses the original-objective anchor. Semantic relevance still requires model
judgment; membership/quoted evidence is not a proof of entailment.

Stable ID = SHA-256 of contract version, immutable objective identity,
requirement ID, target slot ID, category. Exclude message, repair wording,
evidence order, severity, and changing result content IDs. Rephrasing/reordering
retains identity; different targets/categories remain distinct. Model IDs are
not authoritative. Reject conflicting duplicate identities in one review.

A limitation contains typed category (external_validity, unavailable_causal_mechanism,
optional_segmentation, future_validation, unavailable_nonessential_information),
message, optional validated evidence, and related target/requirement when present.
It never alone sets REVISE. PASS requires zero blockers and all deterministic
checks passing. Wrong grain/denominator, false numbers/facts, missing requested
comparisons and selected conflicts remain blocking regardless of acknowledged
uncertainty. Impossible optional follow-ups become limitations; impossible
essential requirements remain blockers and produce a constrained result.
An unsupported causal assertion must be removed/qualified through repair before
it can become an associative limitation. Do not downgrade just because repair
is impossible. Invalid Critic evidence is a validation/provenance failure,
not a candidate defect, silent issue deletion, or a reason to PASS.

## Validation ordering and state machines

One shared policy/helper module; no generic orchestration framework.

1. Build candidate using existing P0.2 hydration/selection and provenance.
2. Run shared deterministic checks: exact bindings/source lineage/citations,
   selected conflicts/structured definitions, then existing completeness.
   These checks precede paid Critic and consume no Critic-loop slot. Preserve
   their real defect detection. Adapt their defects to objective-bound anchors;
   do not delete gates to make tests pass. Existing optional follow-up wording
   must not create objective requirements: `follow_up_analysis` only requests
   repair when necessary to answer/support the original objective; acknowledged
   nonessential unknowns belong in limitations. No new task heuristics.
3. If deterministic checks pass, M runs one budgeted Critic review; S validates
   its returned self-critique with the same contract. Normalize and persist.
4. No blockers: finalize. Essential impossible blocker: finalize constrained.
   Otherwise spend the single finalization repair allowance if capacity exists.
5. Repair only named defects; re-run deterministic validation, then M may use
   one remaining budgeted Critic review; S returns/revalidates self-critique.
   Remaining or newly detected blocker => constrained. Never a second repair.
   Failed/malformed repair/review => constrained with last valid candidate and
   explicit reason; never reuse stale PASS for a changed candidate.

M: audit -> initial Lead candidate -> deterministic gate -> Critic -> at most
one targeted Lead repair -> deterministic gate -> optional final Critic -> stop.
The repair allowance replaces separate pre-Critic completion and post-Critic
remediation passes. Existing initial investigative follow-up can remain bounded,
but cannot run inside finalization repair or pursue optional causal/segmentation
work. Deterministic failure may spend the allowance before the first Critic;
then a model blocker cannot reopen repair. No re-audit.

S: initial Generalist candidate/self-critique -> shared deterministic/validation
boundary -> at most one targeted Generalist repair -> same boundary -> stop.
No specialist or Critic agent is constructed. Preserve the original audit;
self-REVISE gets this opportunity if resources remain. Direct production
finalizers and application runners must not bypass validation through injected
results. Existing narrow evidence-reference correction remains bounded and
must not multiply during the repair invocation; disable nested correction there.

## Ownership, scope and resources

Lead owns synthesis/selection and delegates only the minimal computation needed
to Analyst/Statistician with existing role permissions. Generalist does both
within its existing union. Critic validates; it gains no analytical primitive.
Repair inputs include original objective, exact blockers, candidate, existing
selected result/evidence IDs, and budget remaining. Preserve unrelated correct
findings, selected results, caveats and audit. A complete replacement output is
acceptable only after validating that unrelated work was retained. Definition
change permission is limited to targeted wrong-grain/denominator defects, not a
blanket exemption for every metric. Reuse bound computation for selection/prose.

For synthesis_selection repairs, runtime tool restrictions disallow SQL,
Python, run_analytical and specialist delegation, rather than relying only on
prompt wording. Computation repairs permit existing roles/tools and only a
bounded defect-specific task; instructions must prohibit rerunning audit or
unrelated decomposition. No arbitrary hardcoded query-count limit or new
analytical primitive. Reuse available sources before any new computation.

Keep all RunBudget defaults/configuration ceilings, role turn limits, timeouts,
SQL/Python/chart limits and specialist/Critic counters unchanged. Every actual
model review and computation is charged normally. No global retry. A new
Generalist repair must use the remaining original primary-agent turn allowance
(initial plus repair <= configured Generalist cap), not grant a second full
turn allocation. Track actual primary responses at the response boundary;
unknown consumed capacity must fail closed. Preserve usage/cost accounting.
M's existing bounded Lead invocation caps do not increase; finalization has
fewer invocations. Capacity exhaustion or absent final review capacity yields
constrained, not an assumed PASS. No allowance reset during an attempt.

## Persistence and production scope

Append validation snapshots, candidate/target catalogs needed to interpret
anchors, and one small typed repair record (attempt ID, blockers, status,
prior/repaired selected IDs, stop reason). Keep all raw events, specialist
results, numerical/statistical history, and previous reviews. Latest review is
active; historical issues must not re-block a repaired candidate or disappear
from audit history. Validate complete replacements before mutation; a failed
repair must not overwrite the last valid selected state. Report active blockers
and limitations distinctly and render constrained outcomes honestly.

Expected production files (only change those required):

- `src/schemas/validation.py`, `src/schemas/run_state.py`;
- new `src/agents/finalization.py` for shared catalog/objection validation,
  deterministic preflight and targeted repair policy;
- `src/agents/critic.py`, `skills/critic_validation.md`;

- `src/agents/runtime.py`, `src/agents/model_usage.py` for scoped restrictions
  and remaining Generalist turns; `src/agents/correction.py` only if needed

- `src/orchestration/runner.py`, `generalist_runner.py`, `ledger.py`.

Read dependencies only as necessary: schemas lead/generalist/computation/metrics/
statistics/findings, agents evidence/result_binding/tools/output_contract,
P0.2 and P1.1b contracts, existing relevant tests. No evaluator changes.
